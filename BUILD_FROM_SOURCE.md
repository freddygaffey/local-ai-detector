# Building this extension from source

This file is included in the AMO source-code submission
(`local-ai-detector-<version>-sources.zip`) so a Mozilla reviewer — or anyone
else — can reproduce the exact `.xpi` from this source tree. See
[`docs/release.md`](docs/release.md) for the full release process and
[`docs/install.md`](docs/install.md) for end-user install instructions.

## Toolchain (pinned)

| Tool | Version | Where it's pinned |
|---|---|---|
| Node.js | 25.9.0 | [`.nvmrc`](.nvmrc); `engines.node` in [`package.json`](package.json) accepts `>=22 <26` |
| npm | 11.12.1 | `engines.npm` in `package.json` accepts `>=10` |

Install the pinned Node with `nvm install && nvm use` (or any Node manager
that reads `.nvmrc`), or any Node satisfying `>=22 <26`.

## Steps

```sh
npm ci                    # exact versions from package-lock.json
npm run build:firefox     # -> .output/firefox-mv3 (unpacked)
npx web-ext lint -s .output/firefox-mv3
npx wxt zip -b firefox    # -> .output/local-ai-detector-<version>-firefox.zip
```

`npm ci` runs `postinstall` (`scripts/copy-vendor-assets.mjs`), which copies
the ONNX Runtime Web WASM backend, the `@contentauth/c2pa-web` WASM +
worker, and every bundled dependency's licence text from `node_modules/`
into `public/ort/`, `public/c2pa/` and `public/licenses/` respectively. These
three directories are **derived from `node_modules`** and are intentionally
excluded from this sources ZIP (they are not "source": they're generated by
the exact command above from the pinned dependencies in
`package-lock.json`). Nothing else is generated; the rest of this ZIP is the
complete source for the reviewed extension.

No network access is required at runtime by the extension itself. `npm ci`
does need network access to the npm registry, same as any Node project.

## What to check builds identically

`wxt build -b firefox` (invoked by `npm run build:firefox`, and again as part
of `npx wxt zip -b firefox`) is deterministic given the same
`package-lock.json` and source tree: file names include content hashes, so
identical input produces byte-identical output. `scripts/package.mjs`
(`npm run package`, run by the maintainer before each release) extracts this
same sources ZIP into a scratch directory, rebuilds it, and diffs the
resulting `.output/firefox-mv3` file list and SHA-256 hashes against the
release build — see [`docs/release.md`](docs/release.md#reproducibility) for
the result recorded for this release and any known non-determinism.

## Full multi-target build (not needed for AMO review)

```sh
npm run typecheck
npm test
npm run build            # Chrome -> .output/chrome-mv3
npm run build:firefox    # Firefox -> .output/firefox-mv3
npm run package          # both zips + this sources zip, sizes, hashes
```
